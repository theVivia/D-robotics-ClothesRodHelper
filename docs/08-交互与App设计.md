# 交互与 App 设计

> **这份文档回答：评委/用户看到什么、怎么点、出错时看到什么。**
> 对应实现：`app/index.html`（可交互原型）→ 现场部署到 RDK 网页。

---

## 1. 设计原则（按优先级）

1. **不用学**：3 个按钮能完成 90% 的操作；老人也能用。
2. **看得见**：任何动作都有即时反馈（数字、动画、灯、声音）。
3. **不怕错**：急停永远在，误触可撤销，断网设备自停。
4. **不像遥控器**：像"给衣服排座位"的仪表盘，而不是家电遥控。

> 一句话：**界面是"晾衣杆的实时投影"，不是一堆设置项。**

---

## 2. 信息架构

```
首页（实时杆视图）
├── 模式：手动 / 一键等距 / 智能分配 / 收衣
├── 单元卡片（4 个）：位置、电量、状态、单独拖动
├── 环境：湿度、天气（手动选/传感器）
├── 事件面板：最近 8 条日志
└── 设置（齿轮）
    ├── 目标间距（30—250mm）
    ├── 速度（慢/标准/快）
    ├── 老人模式（大字）
    ├── 重新标定
    ├── Wi-Fi / 设备信息
    └── 关于（版本、许可证、AI 使用说明）
```

## 4. 视觉规范

| 项 | 值 | 说明 |
|---|---|---|
| 背景 | `#0B0D10` | 近黑，不是纯黑（有层次） |
| 面板 | `#12161C` / `#171C24` | 卡片 |
| 主文字 | `#E8EAED` | 高对比 |
| 次文字 | `#8A9199` | 说明 |
| 金色（强调） | `#D4A24C` → `#F0C878` 渐变 | 品牌色，用在数字/主按钮 |
| 湿度蓝 | `#4FA3D1` | 干/潮状态 |
| 湿红 | `#E06C4F` | 湿/告警 |
| 成功绿 | `#4CC38A` | 到位 |
| 圆角 | 14 / 20 px | 大圆角，柔和不硬 |
| 字体 | system-ui / "Microsoft YaHei" / "PingFang SC" | 数字用等宽（`tabular-nums`） |
| 动效 | 300—450ms `cubic-bezier(.2,.8,.2,1)` | 有惯性感，不弹跳过头 |

> 审美锚点：深色 + 高对比 + 一点金 + 科技感。**不要白底，不要糖果色，不要卡通图标。**

## 5. 核心交互

### 5.1 拖动模块

- 手指按住模块左右拖 → 实时跟手；松手后吸附到 5mm 网格。
- 拖动时显示"到邻居的距离"，<30mm 变红并震动（`navigator.vibrate`）。
- 不能穿过邻居（硬约束，视觉上"顶住"停在 30mm 处）。
- 拖动结束 → 发 `POST /api/unit/{id}/move`；按钮"撤销"保留 5 秒。

### 5.2 一键等距

- 点击 → 按钮进入 loading（"规划中…"）→ 模块依次平滑移动（左→右）→ 完成后金色 flash + 数字滚动。
- 全程可急停；急停后按钮变"复位"。

### 5.3 智能分配

- 先让用户标每件衣服的湿度（干/潮/湿 三档，默认"潮"），或由湿度传感器自动。
- 点击 → 湿的间隙大（可视化：间隙条颜色由蓝到红）。
- 顺序不变（P0/P1）：如果用户想让"最湿的排在一起"，提示"需要抬升越障，P2 支持"；不弹虚假的动画。

### 5.4 收衣

- 所有模块移动到右端，间距 60mm；完成后提示"可以收了"。
- 收衣模式自动降速（慢=安全）。

### 5.5 急停

- 红色大按钮，长按 0.3s 触发（防误触），全屏变红边 + 声音。
- 触发后所有单元立刻停，网页显示"已急停 / 检查后复位"。
- 复位需二次确认（"确定周围安全？"）。

---

## 6. 老人模式

- 字号 ×1.4，按钮 ≥56px；
- 只保留"一键排开 / 收衣 / 急停"三个按钮；
- 数字更大，颜色对比更强；
- 语音提示（P2）："衣服已排开，间距十二厘米"。

## 7. 物理交互（模块本身）

| 元素 | 语义 | 说明 |
|---|---|---|
| WS2812 灯环 | 白色呼吸=待机；青色=归零；绿色流动=移动；金色=到位；红色闪=故障；红慢闪=低电 | 评委远远就能看出状态 |
| 按键（短按） | 暂停/继续 | 现场应急 |
| 按键（长按 3s） | 急停/复位 | 物理急停 |
| 蜂鸣器 | 到位"嘀"、故障"嘀嘀嘀" | 可选，展台噪音大时静音 |

## 8. 首次使用（3 步，60 秒）

1. **夹上去**：把模块夹在杆上，听到"咔"（弹簧卡扣）；打开电源，灯变白。
2. **连上**：手机连 `HangFlow-XX` 热点（密码在模块背面贴纸），浏览器打开 `192.168.4.1:8000`。
3. **标定 + 归零**：输入杆长（默认 1200mm）→ 点"标定" → 点"归零" → 完成。

> 现场演示直接跳过 1—2（已配好），只演 3 之后的交互。

## 9. 错误提示文案（人话版）

| 错误 | 界面文案 | 动作 |
|---|---|---|
| 单元离线 | "3 号模块失联了，检查一下电源" | 卡片变灰 + 重连按钮 |
| 堵转 | "2 号被卡住了，我停下来了" | 高亮该单元 + "重试/跳过" |
| 低电 | "4 号快没电了，还能用约 10 次" | 黄色电池图标 |
| 视觉丢失 | "摄像头看不到 3 号，先按估算位置走" | 顶部黄色提示条 |
| 间距过近 | "太挤了，是否收掉一件？" | 建议方案按钮 |
| 急停 | "已急停。确认安全后点复位" | 大面积红色 |

> 文案原则：**说人话、说后果、给下一步**。不要"Error 0x03"。

## 11. 与实现的对应关系

| 设计 | 原型文件 | 现场实现 |
|---|---|---|
| 首页杆视图 | `app/index.html` 的 `.rod` 区域 | 同结构，数据来自 `/ws` |
| 模式切换 | 分段控件 | `POST /api/mode` |
| 拖动 | pointer events | `POST /api/unit/{id}/move` |
| 日志 | 前端数组 | `GET /api/logs` + WS event |
| 急停 | 长按按钮 | `POST /api/estop` |
| 智能分配 | 前端模拟权重 | `POST /api/mode {smart}` |

> 前端先用 mock 数据把交互打磨好（赛前），现场只把数据源从 mock 换成 WebSocket，UI 不动——**降低现场改 UI 的风险**。

## 12. 设计检查清单（演示前过一遍）

- [ ] 手机竖屏 390×844 无横向滚动
- [ ] 深色背景在展台灯下不反光刺眼
- [ ] 数字用等宽字体，跳动时不抖
- [ ] 4 个模块颜色可区分（不仅靠颜色，还有编号）
- [ ] 急停 1 秒内可触达（拇指区）
- [ ] 断网时页面显示"离线"，不白屏
- [ ] 老人模式可一键切换
- [ ] 二维码可扫（对比度、尺寸 ≥3cm）
