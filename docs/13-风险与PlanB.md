## 2. 技术风险深挖（按"最可能先炸"排序）

### R2 打滑（最可能的机械翻车）

- **物理**：硅胶-不锈钢干态 μ≈0.6，湿态 0.3；正压力 15N → 牵引力 9N/4.5N。模块自重 + 2kg 衣物的滚动阻力约 1—2N，**理论够**；但轮面沾灰/杆上有水会掉到临界。
- **信号**：同样 PWM 下速度下降 >20%；编码器位移与视觉位移偏差 >5%。
- **对策**：
  1. 轮面用 50A 硅胶 O 型圈，可换；
  2. 弹簧预压 20N，可调；
  3. 软件限加速度（200mm/s²），避免起步打滑；
  4. 视觉每 300ms 校正。
- **兜底**：改"双轮驱动"（两个轮子夹住杆，像云台轮）——结构件多打印一个轮座即可。

### R3 视觉（第二可能）

- **信号**：识别率 <80%，或 x 抖动 >10mm。
- **对策**：标记从 30mm 加到 40mm；打印用哑光纸；加补光灯；相机离杆从 1.5m 缩到 1.2m；曝光手动锁定。
- **兜底**：纯编码器 + 归零，精度 ±15mm，演示仍可讲"视觉是增强，不是依赖"。

### R4 网络（现场最不可控）

- **信号**：MQTT 延迟 >300ms 或掉线重连。
- **对策**：赛前写死信道；`iw dev wlan0 scan` 选最空；隐藏 SSID；单元只连固定 AP；QoS1 + 序号去重。
- **兜底**：手机热点（SSID/密码贴纸）；ESP-NOW（RDK 插 ESP32-S3 USB 棒，代码预留 `transport=espnow`）。

### R1 时间（最大的风险）

- **信号**：G1 24:00 未过、G3 19:00 未过。
- **对策**：赛前 12 天把每个模块单独跑通；现场"装配流水线"（机械装壳、电控接线并行）。
- **兜底**：§3 降级。

## 3. 功能降级阶梯（与 [docs/11](11-现场48小时执行计划.md) 一致）

| 级别 | 保留 | 砍掉 | 还能讲的故事 |
|---|---|---|---|
| L0 | 4 单元 + 视觉 + 智能分配 + 收衣 | — | 完整产品 |
| L1 | 4 单元 + 视觉 + 等距 + 收衣 | 智能分配 | "等距已实现，湿度加权是下一版" |
| L2 | 4 单元 + 编码器等距 + 手动 | 视觉 | "视觉是增强项，核心机构已跑通" |
| L3 | 3 单元 + 手动 + 收衣 + 网页状态 | 自动 | "概念验证 + 交互原型" |
| L4 | 2 单元 + 单向等距 | 多单元协同 | "最小可行演示" |
| L5 | 实物 + 视频 + 网页 mock | 现场运动 | "工程样机 + 数字化演示" |

**每一级都提前写好台词**，不要现场现编。

## 4. 时间与团队风险

| 风险 | 早期信号 | 动作 |
|---|---|---|
| 有人连续熬夜 | 白天效率下降、脾气差 | 强制轮休，主讲人优先睡 |
| 意见分歧（架构/外观） | 会议超过 15 分钟 | 队长拍板，记录到 ADR，赛后复盘 |
| 队友掉线（实习/课程） | 任务连续 2 天没动 | 重新分配，砍掉其负责的 P1 |
| 只有 1—2 人 | — | 直接选 L3/L4，把精力放在演示与文档 |

## 5. 安全与合规

| 项 | 要求 | 检查 |
|---|---|---|
| 电气 | 18650 带保护板；充电时人不离场；不短路 | 电控每天检查 |
| 机械 | 夹爪无锐边；运动部件有护罩；急停可达 | 机械每天检查 |
| 用电 | 不超插排功率；不私拉电线 | 队长 |
| 拍摄 | 拍评委/队友需同意 | 产品 |
| 开源 | OpenCV/ROS2/Arduino 许可证注明 | 提交前 |

**红线**：任何"演示效果需要绕过安全逻辑"的想法，一律否决。

## 8. 放弃的勇气（写给队长）

- 砍功能不是失败，**在评委面前翻车才是**。
- 每砍一个功能，就把省下的 2 小时投到"演示稳定性"和"讲解"上。
- 记住：评委只记得**你演示成功的那 30 秒**，不记得你少做了一个功能。
