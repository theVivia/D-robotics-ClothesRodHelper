## 2. 进程与线程模型

**一个 Python 进程，多个线程**（48h 的最低故障面）：

| 线程 | 周期 | 职责 | 失败影响 |
|---|---|---|---|
| `MainThread` | — | 装配依赖、信号处理、优雅退出 | 全挂 |
| `CameraThread` | 30 fps | 抓帧 → 最新帧槽（覆盖旧帧） | 视觉降级 |
| `VisionThread` | 30 fps | ArUco → 位置表 | 视觉降级 |
| `PlannerThread` | 10 Hz | 读状态、算目标、发指令 | 停止发指令 |
| `MqttThread` | 事件 | paho-mqtt loop + 收发队列 | 单元失联自停 |
| `WebThread` | — | uvicorn（FastAPI） | 网页不可用 |
| `LoggerThread` | 1 Hz | 落盘 JSONL | 丢日志，不影响控制 |

**共享状态**：一个 `SystemState` 数据类 + `threading.Lock`；所有线程只读写它，不互相直接调用。**禁止**在控制线程里做阻塞 IO。

> 为什么不用 asyncio 全家桶：paho-mqtt 与摄像头采集对 asyncio 不友好，48h 混合模型易出坑。线程 + 队列是最笨但最稳的。

## 3. 通信协议

### 3.1 传输层

- MQTT 3.1.1，broker 在 RDK 本地（mosquitto，端口 1883）。
- 每个单元一个 client id：`hangflow-unit-01`。
- **LWT（遗嘱）**：单元断线时 broker 自动发 `{"online":false}` 到 `hangflow/unit/01/state`。
- QoS：指令 QoS1，状态 QoS0（10Hz 太频繁），事件 QoS1。
- 保留消息：每个单元的最后状态 `retain=true`，网页一打开就能看到。

### 3.2 主题表

| 主题 | 方向 | QoS | 说明 |
|---|---|---|---|
| `hangflow/unit/{id}/cmd` | 中枢 → 单元 | 1 | 运动/停止/归零/配置 |
| `hangflow/unit/{id}/state` | 单元 → 中枢 | 0 | 10Hz 状态（位置/速度/电流/电量/标志） |
| `hangflow/unit/{id}/evt` | 单元 → 中枢 | 1 | 事件（堵转/低电/到达/错误码） |
| `hangflow/unit/{id}/cfg` | 中枢 → 单元 | 1 | 参数（速度、电流阈值、轮径） |
| `hangflow/sys/estop` | 中枢 → 全部 | 1 | 广播急停 |
| `hangflow/sys/presence` | 中枢 → 全部 | 1 | 上线广播/发现 |
| `hangflow/hub/status` | 中枢 → 全部 | 1 | 中枢心跳（5s） |

### 3.3 消息格式（JSON，UTF-8，单条 ≤512B）

**指令** `cmd`：

```json
{
  "v": 1,
  "seq": 42,
  "op": "move",
  "target_mm": 420.0,
  "speed_mm_s": 45,
  "timeout_ms": 10000
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `v` | int | ✓ | 协议版本，当前 1 |
| `seq` | int | ✓ | 单调递增；单元丢弃 `seq <= last_seq` 的旧指令（防乱序） |
| `op` | enum | ✓ | `move` / `stop` / `home` / `ping` / `cfg` |
| `target_mm` | float | move 必填 | 杆坐标，0—L |
| `speed_mm_s` | int | ✗ | 默认 45，范围 10—80 |
| `timeout_ms` | int | ✗ | 默认 10000 |

**状态** `state`：

```json
{
  "v": 1,
  "id": "01",
  "seq": 42,
  "x_mm": 418.6,
  "v_mm_s": 12.0,
  "i_ma": 180,
  "batt_mv": 3920,
  "tof_f_mm": 610,
  "tof_b_mm": 2040,
  "flags": {"homing": false, "moving": true, "estop": false, "fault": 0},
  "uptime_s": 813
}
```

**事件** `evt`：

```json
{"v":1,"id":"01","code":"E03","msg":"stall: 1420mA > 1200mA","x_mm":401.2,"ts":1730000000123}
```

### 3.4 错误码（现场贴墙）

| 码 | 含义 | 现场处置 |
|---|---|---|
| E01 | Wi-Fi 断开 | 检查热点/信道；重启单元 |
| E02 | MQTT 断开 | `systemctl restart mosquitto` |
| E03 | 堵转/过流 | 拿走障碍物，复位 |
| E04 | ToF 前方遮挡 | 检查衣服是否挡住/传感器脏 |
| E05 | 低电（<3.4V） | 换电池 |
| E06 | 归零超时 | 检查左端挡块/归零逻辑 |
| E07 | 非法指令 | 检查 seq/参数 |
| E08 | 位置超时 | 降低速度/检查打滑 |
| E09 | 标定缺失 | 重新标定 |
| E10 | 相机丢失 | 检查 USB/重启 cam 服务 |

### 3.5 时序与超时

```
中枢                      broker                    单元
 │  cmd(seq=42) ──────────► │ ───────────────────────► │ 收下，校验 seq
 │                          │                          │ 执行
 │  ◄──────── state 10Hz ───┤ ◄─────────────────────── │ 每 100ms 上报
 │  ◄──────── evt DONE ─────┤ ◄─────────────────────── │ 到位
 │  若 10s 未到位 → 判超时（E08）并 stop
```

- 单元上电：`WIFI → MQTT → 发布 state + 等 `ping``，收到 `ping` 回 `pong`（保持兼容）。
- 中枢发现：订阅 `hangflow/unit/+/state`，收到即登记；30s 未见标离线。

## 4. REST / WebSocket API

| 方法 | 路径 | 作用 | 示例 |
|---|---|---|---|
| GET | `/api/state` | 全量状态（单元、视觉、模式、间距） | — |
| GET | `/api/units` | 单元列表与在线状态 | — |
| POST | `/api/mode` | 切模式 | `{"mode":"equalize","gap_mm":100}` |
| POST | `/api/mode` | 智能分配 | `{"mode":"smart","humidity":0.82}` |
| POST | `/api/unit/{id}/move` | 手动移动 | `{"target_mm":350}` |
| POST | `/api/estop` | 急停（最高优先级） | — |
| POST | `/api/reset` | 复位（需确认） | — |
| POST | `/api/calibrate` | 重新标定杆轴 | `{"L_mm":1200,"end_margin_mm":50}` |
| GET | `/api/config` | 读配置 | — |
| PUT | `/api/config` | 改配置（杆长/端部余量/墙距/间距/速度/阈值） | `{"rod_mm":1800,"end_margin_mm":50,"wall_mm":150}` |
| POST | `/api/units` | 登记新单元（或加购） | `{"id":"05"}` |
| DELETE | `/api/units/{id}` | 移除单元（二次确认后） | — |
| POST | `/api/mode` | 收衣方向 | `{"mode":"gather","side":"right"}` |
| GET | `/api/logs?n=100` | 最近日志（网页日志区） | — |
| WS | `/ws` | 状态推送（5Hz）+ 事件 | — |

**响应统一格式**：

```json
{"ok": true, "data": {...}, "error": null, "ts": 1730000000123}
```

**错误**：`{"ok":false,"error":{"code":"E07","message":"..."}}`，HTTP 400/409/500。

**安全**：局域网内信任；`/api/estop` 不鉴权（安全优先）；写配置需 `X-Hangflow-Token`（赛前写死，可关闭）。

## 5. 中枢核心逻辑（伪代码）

```python
# controller.py
class Controller:
    def tick(self):
        now = time.monotonic()
        # 1. 更新视觉位置（若新鲜）
        if vision.fresh(now, 1.0):
            for uid, x in vision.latest.items():
                self.state.units[uid].x_visual = x
        # 2. 模式行为
        if self.mode == "manual":
            pass                                   # 用户直接下发
        elif self.mode in ("equalize", "smart", "gather"):
            self.run_plan()                        # 目标变化/未完成时推进
        # 3. 视觉外环
        self.correct_with_vision(now)
        # 4. 安全监控
        self.check_timeout(now)
        self.check_gaps(now)
        # 5. 推送状态
        bus.publish("state", self.snapshot())
```

```python
def run_plan(self):
    targets = plan(...)                 # 见 docs/06
    for uid, x in targets:              # 左→右串行下发
        if not self.units[uid].done:
            self.send_move(uid, x)
            return                      # 一次只推进一个，避免互相干扰
```

**为什么串行**：4 个同时走会互相挡 ToF，且现场看着乱；串行反而**看起来更快**（像多米诺）。

## 6. Mock 模式（无硬件开发的关键）

```bash
python -m software.hub.main --mock
```

- 4 个虚拟单元：一阶惯性 + 速度上限 + 1% 噪声 + 5% 打滑。
- 视觉线程用"真实位置 + 2mm 噪声"伪造。
- 网页/WEB/MQTT 全部真实跑（broker 本地起）。
- 用途：赛前把 UI、规划、异常流程全部调通；现场只替换 `--mock` 为真串口/Wi-Fi。

**验收**：`pytest software/tests` 在 mock 下全绿；`scripts/smoke_test.py` 200 行内完成"等距→校验→急停"。

## 10. 现场改代码的规矩（防止越改越崩）

1. 只在 `feature/现场` 分支改；`main` 保持"能演示"的版本。
2. 每次改完跑 `scripts/smoke_test.py`（mock 模式 20 秒）；不绿不合并。
3. 演示前 30 分钟冻结代码；改配置不改代码。
4. 改完立刻 `git commit -m "现场: ..."`，commit 记录也是"开发过程"证据。
5. 两个人不同时改同一个文件；机械/电控改动前先喊一声。

## 11. 已知实现风险

| 风险 | 表现 | 对策 |
|---|---|---|
| paho-mqtt 重连风暴 | 单元反复上下线 | 指数退避 + 单例 client |
| USB 相机掉帧 | 视觉位置抖动 | 仅用最新帧 + 时间戳新鲜度检查 |
| OpenCV 多线程抢占 | 网页卡 | 视觉线程限 1 核（`taskset`） |
| JSON 解析异常 | 单元收到坏包崩 | 固件 try/catch + 长度限制 |
| 时间不同步 | 日志对不上 | 统一用中枢时间戳，单元只报 uptime |
