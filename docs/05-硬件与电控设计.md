## 1. 硬件总览

三层结构，图纸见 `hardware/wiring/`：

```
[市电 220V]──适配器 5V/5A──┐
                          ▼
                    ┌───────────────┐   Wi-Fi 2.4G 热点 + MQTT
                    │   RDK X5      │──────────────┐
                    │ 4GB / Ubuntu  │              │
                    └──┬────────────┘              │
                       │ USB3.0                    │
                  [USB 摄像头 UVC]                  │
                                                    ▼
        ┌────────────────────────────────────────────────────┐
        │  ClipUnit ×4（套挂单元，各自 1 块 18650，互不供电）   │
        │  ESP32-C3 ←I2C→ AS5600 / VL53L1X                   │
        │      └→DRV8833→ N20 6V → 硅胶摩擦轮压杆自走         │
        └────────────────────────────────────────────────────┘
```

设计原则（决定了后面所有取舍）：

1. **中枢只做"看得见"的事**：视觉、规划、Web、MQTT broker。不直接驱动电机，避免线束跨杆、避免一坏全死。
2. **单元完全自治**：每单元自带电池、自带闭环、自带急停。中枢掉线，单元停在原地不动（fail-safe，不是 fail-unsafe）。
3. **凡是"通电就会动"的路径都不存在**：电机驱动的 nSLEEP 上电默认低电平（休眠=输出高阻），必须 MCU 主动拉高才可能转。

## 4. 中枢外设与接线（摘要）

完整接线表见 `hardware/wiring/wiring-hub.md`。这里只讲三条容易出事的：

1. **供电**：只用官方 5V/5A 适配器或能实测出 5V/5A 的 PD 电源。线必须支持 5A（普通 3A 线在 5A 下压降 0.3—0.5V，X5 会随机重启）。
2. **相机**：P0 用 1 台 USB3.0 UVC 摄像头（广角 100°—120°，1080p30），插在离网口最远的 USB3 口（减少与 2.4G 天线的耦合）。MIPI CSI 作为 P1（现场有奥比中光深度相机，但驱动/标定风险高，不进 P0）。
3. **散热**：X5 满载 10W 级别，演示时是**竖放 + 底部垫高 10mm**，不要平放在桌布上。现场若发放散热片/风扇，装 40PIN 的 5V 风扇——**40PIN 5V 只有 500mA（保守口径），风扇选 ≤300mA 的**，别拿它给大功率外设供电（见 `docs/17` §4）。

### 5.2 三个 strapping 脚的避坑（数据手册 Table 3-1/3-3）

| 脚 | 复位默认 | 启动模式要求 | 我们的处理 |
|---|---|---|---|
| GPIO2 | 悬空 | SPI boot 要求 **1**；手册注：GPIO2 实际不决定启动模式，但**建议上拉防毛刺** | 用作 XSHUT，外接 10k 上拉 → 复位瞬间必为高 ✓ |
| GPIO8 | 悬空 | SPI boot 时不限；但**下载模式下设低会失败**，且参与 ROM 打印选择 | 完全留空，不接外设 ✓ |
| GPIO9 | **内部弱上拉 = 1** | 拉低 → Joint Download Boot（烧录模式） | 只由板载 BOOT 键控制，不外接 ✓ |

一句话规则：**GPIO8 / GPIO9 这根线谁也别碰；GPIO2 只接"上电自然是高"的东西。**

### 5.3 绝对不能用的脚

| 脚 | 原因 |
|---|---|
| GPIO11 | VDD_SPI，Flash 供电脚，只有外部供电改板后才能当 GPIO |
| GPIO12—17 | 接板载 SPI Flash，占用即无法启动 |
| GPIO18 / GPIO19 | USB D- / D+，占用了就没法用 USB 烧录和串口——这台板子的唯一"下载+调试"通道 |

### 5.4 复用脚注意

GPIO4/5/6/7 同时是 JTAG 的 MTDI/MTCK/MTMS/MTDO。用它们做 PWM 和 I2C 是允许的（优先级 3），代价是**放弃 JTAG 硬件调试**——我们本来就用 USB-Serial-JTAG（GPIO18/19），所以无所谓，但要写进文档免得后面有人想接 JTAG 调试器接到 GPIO4 上（那会直接推电机）。

### 5.5 为什么不接 N20 自带的编码器

N20 带编码器版本是 6 线（M1/M2/VCC/GND/C1/C2），很多商家默认发这款。**P0 不接 C1/C2**，理由：

- AS5600 是**绝对角度**，断电重启不需要找零，12 位 = 0.088°/LSB；正交编码器只能增量，丢步/掉电后必须回零；
- 摩擦轮压杆会打滑，"轮子转了多少"不等于"走了多少"，增量编码器在这个场景里给的是假信心，真正的绝对基准是视觉 ArUco + AS5600 组合；
- 省 2 个 GPIO，留给 P1 的左右双 ToF 或第二组驱动。

P1 若要速度前馈，把 C1→GPIO20、C2→GPIO21 即可（脚已留）。

## 6. 关键器件选型说明

### 6.1 DRV8833

- VM 2.7—10.8V，每通道 1.5A RMS / 2A 峰值，内部 H 桥 + 电荷泵，逻辑 3.3V 兼容。
- 单电机只用一个通道：**AIN1/AIN2 驱动，BIN1/BIN2 接 GND，nSLEEP 由 GPIO10 控制**。
- 市售模块（红/蓝小板）**没有采样电阻**（AISEN/BISEN 已接地），所以**没有硬件限流** → 堵转保护只能靠固件（见 §11）。这是本设计里最需要提前说清的一点：不要指望 DRV8833 自己挡住堵转。
- 转速调节用 LEDC PWM 20kHz（高于人耳、低于开关损耗墙），占空比 0—90%（留 10% 给刹车/反向）。

### 6.2 AS5600

- I2C 7 位地址 **0x36**，3.3V 供电，12 位角度，ANGLE 寄存器 0x0E/0x0F（原始值，0—4095）。
- 轴上贴**径向磁铁**（Ø6×2.5mm 或 Ø8×3mm），磁铁中心与芯片中心同心，**气隙 0.5—3mm**；DIR 脚接 GND = 顺时针增大。
- 安装要点：磁铁必须跟着**摩擦轮轴**转，不是跟着电机壳；气隙超 3mm 会丢分辨率、超 5mm 直接读不到。
- 换算：`行走距离 = Δangle/4096 × π × 轮径`。轮径 Ø28mm → 每 LSB = 0.0215mm，10cm 行程 ≈ 4650 LSB（精确 4656，约 1.14 圈），分辨率足够；**真实误差来自打滑**，靠视觉校准兜底。

### 6.3 VL53L1X

- I2C 7 位默认地址 **0x29**，3.3V，4m 量程（长距模式、低环境光），视场角 27°。
- **地址冲突的真实范围**：每个单元一颗，**各单元不在同一条 I2C 总线上（各挂各的 MCU），所以 P0 没有冲突**。冲突只在这两种情况下出现：① 一个单元要装左右两颗 ToF 测两侧；② 未来把多个单元挂到同一个 MCU。两种情况都用同一套办法解决，流程记在这里备用：
  1. 上电先把**所有 XSHUT 拉低**（全部进 shutdown，总线上看不到任何 0x29）；
  2. 逐个把 XSHUT 拉高，等 1.2ms（boot 时间）；
  3. 对刚唤醒的那颗写 `0x0101`（I2C_SLAVE__DEVICE_ADDRESS，新地址），改到 0x2A / 0x2B…；
  4. 全部改完再把 XSHUT 全拉高，此后按新地址访问。
- P0 只装 1 颗时，XSHUT 仍然接 GPIO2：作用变成"**卡死时硬件复位**"——ToF 偶尔会死在 boot 状态，`XSHUT 拉低 100µs 再拉高` 比软件复位可靠。
- 量程衰减（写死在代码注释里）：深色衣物（反射率 <5%）有效量程会掉到 0.5—1m；强阳直射下大幅劣化。我们的邻距需求只有 3—30cm，**量程富余 10 倍以上**，不是瓶颈；瓶颈是**衣物表面倾斜/多回波**，所以每次取 5 帧中位数、丢弃离群值。

### 6.4 WS2812B-2020 单像素

- 1 颗灯，VDD 接 3V3（**略低于规格书 3.5V 下限**，实测多数批次能亮；若出现颜色错乱/不亮，改成接电池正极 VBAT，数据高电平 3.3V 仍满足 0.7×VBAT≤3.3V 的门限）。
- 数据线串 330Ω 抑制反射，VDD-GND 就近 100nF。单像素最大 20mA（白），我们只用 20% 亮度，实际 ≈5—8mA。
- 颜色约定：**绿=就绪，蓝=运动中，黄=低电量，红闪=故障/急停，灭=深休眠**。

### 6.5 电机与摩擦轮

- N20 6V 30rpm（1:298），额定扭矩约 0.8—1.2 kg·cm（**型号间差异大，待实测**）。
- 硅胶驱动轮 Ø28mm（与 `docs/04-机械结构设计.md` 一致）压在 20—35mm 圆杆上。按摩擦系数 μ≈0.6、正压力 8N 估算牵引力 ≈4.8N，扣掉 5kg 承重的等效滚动/滑动阻力（估算 1.5—2N）后仍有 2 倍余量。
- **打滑是设计内的**：宁愿打滑也不要顶死烧驱动。位置误差由 AS5600 + 视觉闭环修正。

## 7. 电源树与防护

### 7.1 电源树

```
18650 (3.0—4.2V, 2000mAh, 带保护板)
  ├─ TP4056（充电：USB-C 5V → 1A 恒流 → 4.2V 截止；含过充/过放保护）
  ├─ 电源开关（SS12D00，拨动式，装在外壳侧面）
  ├─→ MT3608 升压 → +6V0 → DRV8833.VM   [电机轨，峰值 0.7A]
  │                      └ 100µF/16V + 100nF 就近去耦
  ├─→ SuperMini "5V" 脚（= 电池电压 3.0—4.2V）
  │        └ 板载 ME6211 LDO → +3V3 → MCU / AS5600 / VL53L1X / WS2812  [≤120mA]
  └─→ 100k/100k 分压 → GPIO0（ADC）
```

**为什么不从 6V 再降到 3.3V**：6V→3.3V 线性降压效率只有 55%，待机电流会从 37mA 涨到 65mA，待机时间直接从 1.9 天掉到 1.1 天。电池直供 LDO 的效率是 85—89%，且 ME6211 压差只有 ~120mV@300mA，电池掉到 3.4V 时逻辑轨仍有 3.3V，C3 的工作范围下探到 3.0V，所以不存在"电池一低 MCU 就重启"的悬崖。

### 7.2 电量检测分压

- 分压：`VBAT —100kΩ— GPIO0 —100kΩ— GND`，并联 100nF 滤高频。
- 4.2V → 2.10V；ADC 用 ATTEN3（有效量程 0—2500mV，误差 ±35mV，数据手册 Table 5-6）→ 折算电池电压误差 **±70mV**，对"3.6/3.5/3.4V 三档阈值"完全够用。
- 分压常流 `4.2V / 200kΩ = 21µA`，一个月漏 15mAh，可忽略，不需要加 MOSFET 开关。
- 采样方式：连续采 16 次取平均；**只在电机停转时采样**（行走时电池内阻压降 0.1V 量级，会把电量读低）。

### 7.3 上电时序与防倒灌

1. 电源开关 ON → MT3608 起振 → 6V 轨建立（约 5ms）→ DRV8833 VM 就绪，但 nSLEEP 被 10k 下拉 → 输出高阻，**电机不动**。
2. LDO 输出 3.3V → ESP32-C3 启动（约 200ms）→ 固件初始化 → 自检通过后才拉高 nSLEEP。
3. 接 USB 烧录时，板载 VBUS 5V 会与电池路径共存。**烧录请把电源开关关掉**（避免 USB 5V 与 6V 轨同时工作、电机突然动起来），烧完再开。

### 7.4 保护清单

| 威胁 | 器件/措施 | 失效后果 |
|---|---|---|
| 电池过充/过放/短路 | TP4056 模块自带 DW01+8205A | 切断，需重新插充电 |
| 电池反接 | 18650 座建议选带防呆/或串 1N5819（压降 0.3V） | P0 靠外壳防呆，不额外加二极管（省 0.3V 给电机） |
| 电机反电动势 | DRV8833 内部续流二极管 | 模块自带 |
| 电机堵转 | 固件电流/转速判据（§11.1）+ 电池轨 1A 自恢复保险丝 PTC（备选） | 停机 + 红灯 |
| 静电 | 外壳内所有走线不裸露；相机/传感器线加磁环（备选） | — |

## 8. 电流、功耗与续航

> 全部是**设计值**（按器件手册典型值相加），现场必须用 USB 电流表和万用表抽测 1 个单元核对。测法写在 §15。

### 8.1 各器件电流（逐项）

**3.3V 逻辑轨**

| 器件 | 状态 | 电流 | 来源 |
|---|---|---|---|
| ESP32-C3（Modem-sleep，Wi-Fi 已连，160MHz，CPU idle） | 在线待机 | 13mA（外设时钟关）/ 18mA（全开） | 数据手册 Table 5-8 |
| ESP32-C3 Wi-Fi 发射峰值 | 突发 | 335mA（802.11b 21dBm） | 数据手册 Table 5-7（按 DTIM 突发平均下来只有几 mA） |
| AS5600 | 连续采样 | 6.5mA | 器件手册（待实测） |
| VL53L1X | 20ms 测距 / 100ms 周期 | 平均 ≈8mA（含待机） | ST 手册量级，**估算** |
| WS2812B ×1 | 20% 亮度 | 5—8mA | 估算 |
| 分压+上拉 | 常流 | 0.03mA | 计算 |
| **合计（在线待机）** | | **37mA** | 设计值 |

**6V 电机轨**

| 状态 | DRV8833 静态 | 电机 | 6V 轨合计 |
|---|---|---|---|
| 待机（nSLEEP 低） | ≈0.01mA | 0 | ≈0 |
| 待机（nSLEEP 高、不转） | 2.5mA | 0 | 2.5mA |
| 匀速行走（轻载） | 2.5mA | 150mA | **152mA** |
| 堵转 | 2.5mA | 700mA | **700mA** |

### 8.2 折算到电池端（三档）

换算：电机轨功率 / 升压效率 0.85 / 电池电压 3.7V；逻辑轨经 LDO，输入电流 ≈ 输出电流。

| 工况 | 6V 轨功率 | 逻辑轨功率 | 电池端电流 | 备注 |
|---|---|---|---|---|
| **待机（在线）** | 0.015W | 0.122W | **37mA** | Wi-Fi 保活 + 200ms 轮询 ToF + LED 常亮 |
| **匀速行走** | 0.91W | 0.122W | **328mA** | 6V 轨 152mA × 6V = 0.91W，/0.85 = 1.07W → 289mA，+37mA |
| **堵转峰值** | 4.21W | 0.122W | **1377mA** | 4.21/0.85 = 4.95W → 1340mA，+37mA |

计算过程（匀速行走，可直接抄进 PPT）：

```
P_电机 = 6.0V × 0.150A = 0.90W
P_驱动 = 6.0V × 0.0025A = 0.015W
P_6V   = 0.915W
P_电池 = P_6V / η_boost = 0.915 / 0.85 = 1.076W
I_电机(电池侧) = 1.076W / 3.7V = 291mA
I_总 = 291mA + 37mA(逻辑) = 328mA
```

堵转时 1.38A 对 2000mAh 电池是 0.69C，保护板（2—3A）不会动作，MT3608 输出 0.7A 也在 1A 设计余量内——**堵转在电气上撑得住，靠固件在 1.5s 内退出**。

### 8.3 低功耗待机档

| 档位 | 策略 | 电池端电流 | 一块电池能撑 |
|---|---|---|---|
| 在线待机 | Wi-Fi 保活、ToF 200ms 轮询、LED 常亮 | 37mA | **45.9h ≈ 1.9 天** |
| 低功耗待机 | Wi-Fi 保活、ToF 2s 轮询（VL53L1X 进 standby）、LED 灭 | 23mA | **73.9h ≈ 3.1 天** |
| 深休眠 | Wi-Fi 断、light-sleep 130µA（数据手册 Table 5-9）、按键/定时唤醒 | 0.135mA（含保护板 5µA） | 理论 **525 天**（实际按自放电限，约 8—12 个月） |

> 深休眠档收不到 MQTT 命令，只用于运输/长期存放。演示时用"在线待机"或"低功耗待机"。

### 8.4 可执行次数

一次典型动作 = **移动 80mm**（间距从约 40mm 拉到约 120mm 的常见调整）：

```
轮周长 = π × 28mm = 87.96mm（Ø28 驱动轮，与机械文档一致）
转数 = 80 / 87.96 = 0.91 转
转速 30rpm（额定值，见 §6.5）→ 纯行驶 = 0.91/30 × 60 = 1.82s
加梯形加减速、定位微调、视觉 settle，保守取 4s（机械行驶 1.8s + 2.2s 余量）
单次电荷 = 0.328A × 4s / 3600 = 0.364mAh
含定位微调/视觉校准开销 ×1.5 → 0.55mAh/次
可用容量 = 2000mAh × 0.85（保护板截止+老化+低温）= 1700mAh
可执行次数 = 1700 / 0.55 ≈ 3100 次
（只算纯动作能量：1700 / 0.364 ≈ 4670 次）
```

**这个数字要正确解读**：动作本身几乎不耗电（4 秒的电机能量 ≈ 0.36mAh），**真正吃电的是待机**。所以：

- 演示 48 小时：4 个单元每单元一块电池，按"在线待机"1.9 天算，**第一天晚上必须换电池或充电**；
- 一次完整演示（4 单元 × 30 次调节）总消耗 ≈ 4 × 30 × 0.55mAh = **66mAh**，占一块电池 3.9%——**演示时间再长也不是问题，问题只是"放在那里待机"**。

### 8.5 结论（答辩口径）

> 一块 18650 可以让一个套挂单元连续在线待机约两天，或者执行三千次以上调整；单次调整只花 0.4mAh，整块电池的寿命主要由"挂在杆上等命令"的待机电流决定。这也决定了产品化的方向：把 Wi-Fi 保活换成定时唤醒 + 被动红外/称重触发，待机就能从两天变成两个月。

## 9. 中枢现场供电

### 9.1 需求

- 官方要求：**5V/5A**（25W）。这不是虚标——X5 四路 USB3 每口给 1A、BPU 满载、Wi-Fi 发射叠加，峰值余量必须够。
- 我们的实际负载估算：静置 + Wi-Fi + 1 台 UVC 相机 ≈ **6—8W（1.2—1.6A@5V）**；跑 YOLO 推理 + 网页推流 ≈ **10—14W（2.0—2.8A）**。**以上为估算，待现场用 USB-C 电流表实测**。
- 演示时长：单次演示 10—15 分钟，全天断续使用 6—8 小时。

### 9.2 三条供电路线（按可靠性排序）

| 方案 | 配置 | 可行性 | 风险 |
|---|---|---|---|
| **A. 市电 + 官方 5V/5A 适配器**（首选） | 220V 排插 + X5 配套适配器 + **支持 5A 的 Type-C 线** | 最高 | 现场插座位置/排插不够；被人踢线 |
| B. PD 充电宝 + 5V/5A 直出 | 65W 以上 PD 充电宝，确认 PDO 里有 **5V/5A** 或 **PPS 3.3—11V/5A** | 可行 | **最关键的风险**：多数 65W 充电宝的固定 PDO 只有 5V/3A（15W），X5 峰值会掉压重启 |
| C. PD 诱骗 20V + 降压 5.1V/6A | 充电宝 20V/3.25A（65W）→ 诱骗模块 → 同步降压（XL4015/MP1584 类，需 ≥6A 或加散热）→ Type-C 母座 | 可行但要多带两块板 | 降压模块纹波/发热；接线多一个故障点 |

### 9.3 充电宝选型建议（含 PPS 风险提示）

**要买的**：
- 容量 **20000mAh（74Wh）** 起，原因：X5 按 12W 算，20000mAh 可用 62.9Wh → **约 5.2 小时**；12000mAh 只有 3.1 小时，撑不住一整天。**带 20000mAh 上飞机需注意 100Wh 限制（74Wh 安全）。**
- 输出口标称 **≥65W**，且**产品页明确写"5V/5A"或"PPS 3.3—11V/5A"**。只写"65W"不够。
- 优先选"支持 PD3.0 PPS + 5V/5A 固定档"的型号；避开只标 5V/3A 的"笔记本充电宝"。

**PPS 风险（必须在赛前实测，不能只看参数）**：
- PPS 是**可调电压档**，需要受电端主动协商。RDK X5 的 PD 受电芯片如果只认固定 PDO，充电宝给的是 5V/3A；如果认 PPS，才可能拿到 5V/5A。
- 表现：**开机正常，一跑推理就黑屏重启**，或者 HDMI 闪一下。这种"看起来能用"的故障最坑，一定要用**满载测试**验收：跑 30 分钟推理 + 网页推流，同时盯 5V 轨电压。
- 判据：**5V 轨在满载下不得低于 4.75V**，USB-C 电流表读数 ≤ 4.9A 且不掉压。

### 9.4 断电保护

1. **硬件**：备一个 5V/2A 的"UPS 移动电源"（带边充边放），串在适配器和 X5 之间。它只能给 X5 续 30—60 秒（2A 不够满载），**作用只是给"优雅关机"争取时间**，不是续航。
2. **软件**：根文件系统减少写（日志走 tmpfs、`sync` 上限），避免突然断电烧 SD 卡。SD 卡烧坏是这类板子最常见的现场事故。
3. **流程**：演示前 30 分钟充满所有充电宝；演示脚本里写"上台前先确认电源指示灯绿色常亮（不是闪烁）"。
4. **备份**：带 2 张已经烧好系统的 SD 卡（同镜像），一张当场换。现场再烧一次系统至少 20 分钟，48H 里输不起。

## 10. 通信：RDK 热点 + MQTT

### 10.1 拓扑

```
手机 ─┐
      ├─ 2.4GHz Wi-Fi（RDK 开热点，SSID: HangFlow）─ RDK X5 (10.42.0.1)
单元 ─┘                                              ├ FastAPI :8000（手机网页）
                                                     └ mosquitto :1883（单元上报/下发）
```

**关键约束**：ESP32-C3 **只支持 2.4GHz**，所以 RDK 的热点必须开在 2.4GHz（X5 本身支持 5GHz，但不能给单元用）。手机和单元连同一个 2.4G 热点。

### 10.2 现场配置步骤（RDK 上执行）

```bash
# 1) 扫一下现场 2.4G 占用，挑最空的信道（1/6/11 三选一）
sudo iw dev wlan0 scan | grep -E "freq|SSID|signal" | head -60
#    freq:2412 = ch1, 2437 = ch6, 2462 = ch11

# 2) 开 2.4G 热点（band bg = 2.4GHz；强制 20MHz 带宽，拥挤场馆别用 40MHz）
sudo nmcli device wifi hotspot ifname wlan0 ssid HangFlow band bg channel 6 password hangflow2026
#    默认网段 10.42.0.1/24，DHCP 自动分配

# 3) 关省电，减少 MQTT 延迟抖动
sudo iw dev wlan0 set power_save off

# 4) MQTT broker
sudo apt install -y mosquitto mosquitto-clients
```

### 10.3 信道建议

- 优先 **1 / 6 / 11** 里最空的那个（三者互不重叠，别用 3、8 这种，会同时干扰两个信道）。
- 黑客松现场几十个 AP + 一堆 2.4G 麦克风/投屏器，**如果 2.4G 实在脏**，Plan B 是：RDK 走有线千兆（现场一般有网口）+ 一台随身 2.4G 路由器当 AP（比板载 Wi-Fi 的发射功率和天线好），或者直接用手机热点（注意手机热点常见"无设备活动 10 分钟自动关闭"，要在设置里关掉）。
- ESP32 侧固定静态 IP（10.42.0.11—.14，按单元编号），避免 DHCP 抖动导致 MQTT 重连。
- MQTT 参数：`keepalive=15s`、`clean_session=true`、QoS1（命令）、QoS0（状态上报，丢一帧无所谓）、**必须设 LWT**（掉线时 broker 自动发"offline"），主题与报文格式见 `docs/07-软件架构与通信协议.md`（本文不重复定义）。

### 10.4 通信失效策略（和 §11 呼应）

单元 **5s** 收不到心跳/命令 → 保持当前位置但禁止运动；**10s** → nSLEEP 拉低（电机高阻）。也就是"中枢死了，单元就地站住"，绝不出现"最后一条命令是一直往前走"。

## 11. 安全与失效保护

### 11.1 堵转保护（本设计唯一真正的过流防线）

DRV8833 模块没有采样电阻 → **只能靠固件**。判据：

```
条件 A：PWM 占空比 ≥ 40%
条件 B：300ms 内 AS5600 角度变化 < 2 LSB（≈0.18°，约 0.037mm）
A 且 B 成立 → 记一次"疑似堵转"
连续 3 次 或 累计 1.5s → 立即降到 0% → nSLEEP 拉低 → 红灯闪 → MQTT 上报 fault=STALL
```

为什么用"角度没变"而不是"电流大"：我们没有电流采样，但**堵转 = 电机在使劲但轮子不转**，这个现象 AS5600 直接能看见，判据更本质，而且对"打滑"和"卡死"一视同仁——两种情况都应该停。

### 11.2 看门狗

- `esp_task_wdt`（2s）：主循环喂狗，MQTT/控制任务任一卡死 → 复位。
- 复位后默认状态：nSLEEP 低（硬件 10k 下拉保证），**电机一定不动**；固件启动自检通过后才允许运动。
- 可选加强：ESP32-C3 内置 RTC watchdog（`esp_task_wdt` 之外的硬件 WDT），代码里开 CONFIG_ESP_TASK_WDT。

### 11.3 低压保护（四档）

| 电池电压（停转时测） | 动作 |
|---|---|
| ≥3.6V | 正常 |
| 3.6V—3.5V | 黄灯，允许继续，拒绝"长距离归拢"这类大动作 |
| 3.5V—3.4V | 黄灯闪，**禁止起步**（只允许停在原地/微调） |
| <3.4V | nSLEEP 低 + 红灯闪 + 上报 `fault=LOW_BAT`，进入低功耗待机 |
| <3.3V（或 10 分钟无命令） | 深休眠（light-sleep，按键唤醒） |

阈值取 3.5V 而不是 3.0V（保护板才 2.5V），是因为 3.5V 以下电池内阻陡增、压降会让逻辑轨进入压差区，宁可早停。

### 11.4 急停（三条独立路径，任何一条都能停）

| 路径 | 实现 | 响应时间 |
|---|---|---|
| **App/网页急停** | 网页按钮 → FastAPI → MQTT QoS1 广播 `cmd=ESTOP` → 单元回调里第一时间 nSLEEP 低 | 100—300ms（受 Wi-Fi 影响） |
| **模块按键长按 3s** | GPIO1 低电平持续 3s（短按只是配网/自检，防误触） | <50ms（本地中断） |
| **物理断电** | 外壳侧面电源开关 | 瞬间（电机惯性 <1 轮转） |

设计上"断电"永远是最可靠的急停，所以**开关必须放在手能够到的位置**（外壳侧面偏下），不要藏在夹爪内侧。

### 11.5 防夹

- 运动方向上的 VL53L1X 读数 < 30mm 且电机正朝该方向走 → **反向 200ms 再停**（不是直接停，直接停会让夹点保持压力）。
- 防夹阈值 30mm > 最小安全间隙 30mm 的设计值，留了 0 余量——**这条要在现场调试时按真实杆径/衣厚修正**，宁可放大到 40mm。
- 硬件层面的兜底：摩擦轮压紧力按"打滑优先"设计（见 §6.5），夹到手指最多打滑，不会夹伤。

## 12. 布线、装配与工艺

| 项 | 规定 | 原因 |
|---|---|---|
| 电机线 | AWG26 硅胶线，双绞 | 减少 PWM 干扰 I2C |
| I2C 线 | AWG28，SDA/SCL 双绞，长度 ≤100mm | 400kHz 下短线才稳 |
| 电源线（电池→板） | AWG24，长度 ≤80mm | 1.4A 峰值时压降可控 |
| 接地 | 电机地与逻辑地**单点汇合**在 TP4056 的 GND 焊盘 | 避免电机电流流过 I2C 参考地 |
| 连接器 | 电池用 XH2.54 带扣；电机用 PH2.0；传感器用 GH1.25 或直接焊 | 防振脱落 |
| 去耦 | 每颗 IC 100nF；6V 轨 100µF/16V；电池入口 100µF/16V | — |
| 走线固定 | 所有线用扎带/热熔胶固定在壳内，**活动件（摩擦轮、夹爪）周围留 5mm 净空** | 防磨破皮 |
| 极性 | 电池座丝印标 +/−；所有插头做防呆（XH 有方向） | 反接会烧 TP4056 |

**上电检查清单（每次新装一台必做）**：
1. 万用表二极管档量电池座正负极是否短路（应无读数）；
2. 不接电机，上电，量 6V 轨（应为 5.9—6.1V）、3.3V 轨（3.25—3.4V）；
3. 串电流表量待机电流（应 ≈35—45mA）；若 >100mA 立即断电查短路；
4. 接电机，发一条 20% 占空比命令，看轮子是否转、电流是否 ≈200mA；
5. 手按住轮子模拟堵转，1.5s 内应自动停 + 红灯闪。

## 14. 未验证风险（3 个最大的）

| # | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| **R1** | **中枢 5V/5A 电源协商失败**：PD 充电宝只给 5V/3A，X5 满载时掉压重启。表现为"开机正常、跑推理就黑屏" | 中 | 致命（演示中断） | 赛前用满载测试验收；主用官方适配器；带 2 根 5A 线 + 1 个 USB-C 电流表 |

| **R3** | **N20 电机参数分批差异**：标 6V/30rpm/0.7A 堵转，实物可能是 25rpm 或 1.2A 堵转，直接影响堵转判据与续航数字 | 高 | 中（要重调阈值） | 到货先测空载/堵转电流与转速；固件把堵转判据做成可配置参数；多买 2 个备用电机 |
