## 2. 项目身份

- 中文名：**衣序**
- 英文名：**HangFlow**
- 仓库：`theVivia/D-robotics-ClothesRodHelper`（当前为空仓库，尚无 commit）
- 一句话：**不换晾衣杆，套上就能让衣服自己让出风道。**
- 产品形态：若干"套挂单元"夹在既有晾衣杆上，每件衣服挂在单元上；单元沿杆自走；RDK 视觉中枢看全场、算间距、发指令；手机 App / 网页手动或自动调节。

## 3. 需求与价值（口径统一）

**真实痛点（上海/南方梅雨、回南天、冬季阴干）**
1. 衣服挤在一起 → 中间无风道 → 外干内湿、返潮、异味、霉斑；实测衣间距 <5cm 时内部湿度显著高于环境。
2. 手推衣服：要么推不到位，要么把杆推歪/挂钩掉落；高杆够不着；湿衣服重。
3. 晾被子/大件与晾袜子需要不同间距；现有电动晾衣架只能升降，不能调间距。
4. 夜间/下雨要收，白天要摊开；反复手动。

**价值主张**
- 对用户：干得更快（风道）、不返潮、不用爬高、杆子不用换。
- 对场景：出租屋/老小区/宿舍/阳台栏杆等**已有杆**场景，零安装改造。
- 对评委：不是"又一个晾衣架"，而是**把晾晒从经验变成参数**的"空间调度器"——可延展到衣柜、阳台、烘干房。

**量化目标（演示口径，别写成实测结论）**
- 同等条件下衣物间平均间隙从 3—5cm 提升到 10—15cm；
- 单次调整 ≤ 45s（4 件衣服，典型 30s；速度刻意压慢以降低打滑与噪音）；
- 定位精度 ±5mm，最小安全间隙 3cm；
- 单模块承重 5kg。

> **成本口径（2026-11-23 Lead 锁定，所有人遵守）**
> - **单套挂单元（打样）≈ ¥150**：电控+电池 ≈ ¥86.5，机械（打印/轴承/轴/弹簧/五金/硅胶轮）≈ ¥65。机械 BOM 与电控 BOM 里的 N20、硅胶轮**只计一次**。
> - **整机打样（4 单元 + 相机 + 演示架 + 线材，不含 RDK）≈ ¥850**；含 RDK X5（¥549）≈ **¥1,400**。
> - **量产（1 万台）单单元 ≈ ¥125，整机（4 单元 + 中枢，不含 RDK）≈ ¥650**；更低价要等 5 万台 + 中枢复用手机算力。
> - **零售定价**：Lite（2 单元 + 手机直连）**¥399**；Pro Core（4 单元 + ESP32 网关）**¥999**；Pro Vision（4 单元 + RDK 视觉中枢）**¥1,899**；加购单元 **¥199**。
> - 答辩时只能说这一套数字；"¥400 整机""比电动晾衣架便宜八成"等旧口径作废（已从 README/00/12 删除）。

> **参数化与安装边界（2026-11-23 用户反馈后锁定）**
> - **杆长 0.8—2.4m**（默认 1.2m 演示），两端端部余量 50mm（可按法兰座厚度 30—80mm 调）。
> - **单元数量 2—8 个**（默认 4），按地址 01—08 识别，可增删；增删后重算布局，挤不下要显式告警。
> - **杆中心到墙 ≥120mm（建议 150）**；<80mm 时 UI 提示"衣摆可能蹭墙"。
> - **两端有墙**：单元不越过端部挡块（所以 P2 抬升换序在壁龛里更不现实）；收衣只向有空间的一侧收。
> - **伸缩杆**：接缝（常见 25/22mm，2—3mm 台阶）设为"禁停区"，过缝降速 20mm/s；弹簧行程 ≥8mm。
> - **>1.8m 长杆**：建议加中间吊撑（从上方吊，不挡杆面）；>2.4m 必须加。
> - 产品口径：**编号是模块地址，不是衣服编号**（UI 写"单元 01"）。

> ⚠️ **尺寸口径（2026-11-23 修正，所有人必须遵守）**：衣架是平行挂的，沿晾衣杆方向的占位不是衣架宽度（约 42cm），而是**衣物挂上后的厚度投影 t_i**：干衣约 2—4cm，湿衣约 3—6cm（羽绒/毛巾更厚）。所以间距规划的自由度是 `L = Σt_i + Σg_i`，演示杆 1.2m 挂 4 件绰绰有余（4×5cm + 3×10cm = 50cm）。视觉检测看到的是沿杆的"衣肩带"，宽度约 4—8cm。**不要把 w_i 当成衣架宽度去做规划，否则所有数字都错。**

## 4. 系统形态（锁定，别再发散）

```
        ┌──────────── RDK X5（中枢）────────────┐
        │ 摄像头（USB/MIPI）→ 视觉定位/测距      │
        │ 间距规划器 → MQTT → Web App（FastAPI） │
        └───────────────┬───────────────────────┘
                        │ Wi-Fi (2.4G, RDK 开热点)
        ┌───────────────┴───────────────────────┐
        │  套挂单元 ×N（ESP32-C3 + N20 + 编码器）│
        │  夹在杆上，自带摩擦轮自走、18650 供电   │
        └───────────────────────────────────────┘
```

- **模块化套挂单元（ClipUnit）**：C 形夹爪夹住 20—35mm 圆杆；顶部硅胶摩擦轮压杆驱动；下方两个惰轮防翻转；侧面挂衣钩；ESP32-C3 + DRV8833 + AS5600 磁编码 + VL53L1X 邻距 + WS2812 + 18650；3D 打印外壳。
- **中枢（Hub）**：RDK X5，Ubuntu 22.04 + ROS2 Humble/TROS；USB 摄像头做 ArUco 视觉基准 + 可选深度相机做衣物体积；FastAPI 提供手机网页；MQTT 控模块。
- **交互**：手机网页（无需装 App）、模块上的按键/LED、语音（P2）。
- **模式**：手动（滑杆/档位）/ 一键等距 / 智能分配（按湿度、衣长、材质）/ 收衣归拢 / 防夹急停。

## 5. 为什么必须是 RDK（答辩口径）

1. 多路视觉 + 实时推理：X5 的 BPU 跑 YOLO/分割，CPU 跑标定、规划、Web 服务，一颗板全包。
2. 40PIN + USB + Wi-Fi + CANFD：接深度相机、舵机、传感器、下位机都行，扩展性支撑"产品化"。
3. ROS2/TROS 生态：后续接机械臂、升降晾衣架、家庭机器人。
4. 成本/功耗：整机可做到"一个中枢带 6—8 个单元"，中枢可复用为家庭其他设备网关。

## 6. 关键设计决策（Locked）

| 决策 | 选择 | 备选/理由 |
|---|---|---|
| 驱动方式 | 单元自走（摩擦轮压杆） | 备选：杆上挂导轨+同步带（更稳但"套挂"感弱、成本高）；丝杠（行程短） |
| 电机 | N20 6V 减速电机（约 30rpm）+ 直驱 Ø28 轮；位置保持靠编码器闭环 + H 桥短路刹车，**机械自锁为 P1**（自锁蜗轮 ≥20:1 会把速度压到 1.5rpm，48h 做不出来） | 备选：飞特总线舵机（现场有，但连续旋转与夹持不便） |
| 位置反馈 | 轮式编码器（AS5600）+ 视觉 ArUco 校准 | 备选：纯 ToF 相对测距（累积误差） |
| 通信 | Wi-Fi + MQTT | 备选：ESP-NOW（需 USB 网卡）；UART 滑环（不可行） |
| 视觉 | 单目 USB 相机 + ArUco 标记；深度相机为 P1 | 深度相机现场提供（奥比中光），但驱动/标定风险高 → 不进 P0 |
| 中枢 | RDK X5（现场发放） | S100 算力更强但生态资料少，48H 不冒险 |
| 供电 | 每单元 18650（3.7V 升 6V） | 备选：杆端滑触线（可靠但结构复杂） |
| 演示规模 | 4 个单元 + 1.2m 杆 | 现场最多做 6 个；P0 只保证 3 个能动 |
| 交互载体 | 手机网页（RDK 热点 + 局域网） | 不装 App，评委扫码即用，演示风险最低 |

## 8. 写作规范

- 中文；结论先行；**技术方案必须翻译成人话**（用户明确要求），术语第一次出现给一句解释。
- 所有数字标注是"设计值 / 估算 / 实测"。不要把估算写成实测。
- 引用外部资料给链接；不编造型号、价格、论文。
- 每份文档开头一句话说明"这份文档回答什么问题"。
- 机械/电控图纸用 SVG 或 ASCII + 尺寸标注，能落到 CAD 的参数写清楚。
