## 2. 线程模型

| 线程 | 周期 | 职责 |
|---|---|---|
| Camera | 30fps | 抓帧，最新帧槽 |
| Vision | 30fps | ArUco 读 ID/中心，输出 `{id: x_mm}` |
| Planner | 10Hz | 链模型、目标长度、超限检查、下发 |
| MQTT | 事件 | paho-mqtt，收 state/evt，发 cmd |
| Web | — | FastAPI + WebSocket 5Hz 推送 |
| Logger | 1Hz | JSONL 落盘 |

共享 `SystemState` + 锁；控制逻辑不放中枢（长度闭环在单元本地）。

## 3. 链模型（中枢核心）

排列：`墙/边缘 — 调节器0 — 衣架1 — 调节器1 — … — 衣架K — 调节器K — 墙/边缘`，共 **K+1 个调节器、K 个衣架**。每个调节器有两端夹持状态 `clamp_l / clamp_r`（锁/松）。

已知调节器长度 `L_i`（i=0…K）、衣架厚度 `t_h=10mm`、左右安装余量 `m_l/m_r`：

```
x_1 = m_l + L_0 + t_h/2
x_{i+1} = x_i + t_h + L_i          (i = 1…K−1，内部段)
右墙约束：x_K + t_h/2 + L_K + m_r ≤ 杆长
```

- `x_i` 为第 i 个衣架中心（左墙/挡块 = 0）。
- 内部段 `L_i = g_i`（净风道）；端部段 `L_0 / L_K` 决定两端留白与预紧（伸出顶墙 5—10mm）。
- 视觉给出调节器中心 `c_i`，接缝 ≈ `c_i ± L_i/2`；与模型比较，偏差 >3mm 时修正。
- 总链长 `Σ_{0}^{K} L_i + K·t_h + m_l + m_r` 必须 ≤ 杆长；否则拒绝执行。
- **夹持状态参与模型**：只有"锁住的一端"才能作为绝对基准；两端都松的段不能用于定位（只能滑动/取下）。

## 4. MQTT 协议

### 4.1 主题

| 主题 | 方向 | QoS | 说明 |
|---|---|---|---|
| `hangflow/unit/{id}/cmd` | 中枢→单元 | 1 | `set_length` / `stop` / `home` / `ping` |
| `hangflow/unit/{id}/state` | 单元→中枢 | 0 | 10Hz：长度、电流、电量、限位标志 |
| `hangflow/unit/{id}/evt` | 单元→中枢 | 1 | 到达/卡死/限位/低电 |
| `hangflow/sys/estop` | 中枢→全部 | 1 | 急停 |
| `hangflow/sys/presence` | 双向 | 1 | 上线/发现 |

### 4.2 指令

```json
{"v":2,"seq":42,"op":"set_length","target_mm":100.0,"speed_mm_s":5.0,
 "clamp":{"left":"lock","right":"free"},"timeout_ms":30000}
```

| 字段 | 说明 |
|---|---|
| `v` | 协议版本 2（v1 是 1，字段不同，不兼容） |
| `seq` | 单调递增，单元丢弃旧指令 |
| `target_mm` | 目标长度；内部段 100—220，端部段 30—120；超出拒绝 |
| `speed_mm_s` | 3—8mm/s（T8 8mm 导程 + 30rpm ≈ 4mm/s），默认 5 |
| `clamp` | 双端锥面收口夹头动作：`lock`/`free`；**两端都 free 时拒绝 set_length** |
| `timeout_ms` | 默认 30s（伸长 20cm 约 40s，注意） |

> 夹持动作顺序由中枢决定：先锁固定端 → 再伸长/缩短 → 到位后锁另一端。单元只执行，不自己猜。

### 4.3 状态

```json
{"v":2,"id":"02","seq":42,"length_mm":99.6,"target_mm":100.0,
 "clamp_l":"lock","clamp_r":"free",
 "i_ma":180,"batt_mv":3920,"flags":{"moving":false,"min_limit":false,"max_limit":false,"fault":0}}
```

### 4.4 事件

| 码 | 含义 | 现场处置 |
|---|---|---|
| E01 | Wi-Fi 断开 | 检查热点 |
| E02 | MQTT 断开 | 重启 broker |
| E03 | 丝杆卡死（PWM 在给、AS5600 不动） | 清除异物、复位 |
| E04 | 超行程（<40 或 >220） | 检查限位/标定 |
| E05 | 低电 | 换电池 |
| E06 | 长度超时 | 降速/检查卡阻 |
| E07 | 非法指令 | 检查参数 |
| E09 | 标定缺失 | 重新标定 |
| E10 | 夹持未锁/夹持失败 | 重新锁端；检查微动/凸轮 |

## 6. 一次"一键等距"的时序

```
用户点按钮
 ├─ web: POST /api/mode {equalize, gap_mm:100}
 ├─ planner: 读 K（视觉 ID 数）、杆长、端部余量
 ├─ planner: 目标 L_i = 100mm（每段），检查 ΣL+K×10 ≤ 可用
 ├─ planner: 视觉 ID 确认（01/02/03 都在，且顺序与配置一致）
 ├─ planner: 按"从左到右"下发 set_length（或从右到左，见 §7）
 ├─ 单元: 本地闭环伸长，10Hz 上报 length
 ├─ vision: 每 300ms 读圆柱中心 → 与模型比对 → 偏差 >3mm 修正目标
 ├─ 全部到达 → planner 发 done → 网页显示"间距已排开"
 └─ 日志写入 logs/run-*.jsonl
```

**速度预算**：单段 10cm 以 5mm/s 约 20s；3 段串行 60s。现场演示可先预置到接近目标（上电归位/上次状态），一键动作只走 2—3cm，约 10—15s。

> **答辩口径**：*"它不是每次都从零开始走，上一次的位置记着；一键调整通常只动几厘米。"*

## 7. 调节顺序与双端锥面收口夹头策略

链是 `左墙/挡块 — L0 — 衣架1 — L1 — … — 衣架K — LK — 右墙/挡块`，每个调节器两端各有夹持。**不再有卷簧**：端部段锁住外端、伸出顶墙，给整条链预紧；内部段每次只放开一端。

**推荐顺序（从左到右建立基准，再从右到左微调）**：

1. **锁基准**：端部段 0 的左端锁死在左挡块侧，伸出顶墙（预紧 5—10mm）。
2. **逐段定位**：内部段 i 从 0 到 K−1：
   - 锁左端（已由前一段/衣架提供基准）；
   - 松右端，伸长/缩短到目标 `L_i`；
   - 右端锁死，成为下一段的左基准。
3. **收尾**：端部段 K 锁外端、伸出顶右墙预紧。
4. **收衣**：反向——从右到左，先解右端、缩短、再锁；端部段最后回缩。

**规则**：

- **绝不两端同时松**去伸缩（段会滑走，长度也不准）；
- **绝不所有电机同时动**（负载叠加、夹持点受剪力）；
- 每一步 100ms 间隔，到位后先发夹持、再发下一段；
- 如果某段夹持反馈"未锁"，拒绝它的伸缩指令并报警（E10）。

> **答辩口径**：*"它不是靠弹簧拉紧的，是每段自己锁死在杆上；锁一端、伸另一端，所以位置是绝对的。"*

## 8. 视觉 ID 识别（智能识别）

- 每个圆柱顶部贴 **ArUco `DICT_4X4_50`，ID 01—09（K+1，K=2—8），边长 30mm**；相机 1280×720，距离 1.2—1.5m，正对杆。
- 识别结果：`{id: {"cx": px, "x_mm": 杆坐标, "conf": 0—1}}`。
- **顺序校验**：按 `x_mm` 排序得到实际顺序；与配置的 `01,02,03` 比较。不一致 → 提示"请检查安装顺序"（不自动改序）。
- **接缝/衣架位置**：圆柱中心 ± L_i/2；衣架中心 = 接缝中心；与长度模型融合（卡尔曼/加权平均）。
- **失败降级**：连续 1s 丢 ID → 用长度反馈推算位置，网页提示"视觉遮挡"；不影响长度闭环。
- 反复读错 ID（连续 3 帧）→ 丢弃并告警；不允许"猜"。

## 12. 与 v1 协议的区别

| v1 | v2 |
|---|---|
| `op:"move", target_mm`（位置） | `op:"set_length", target_mm`（长度） |
| `x_mm`（杆坐标） | `length_mm`（圆柱长度） |
| 模块 ID 01—04，自走 | 圆柱 ID 01—09（K+1，K=2—8），固定 |
| ToF/电流/心跳 | 长度限位/卡死/心跳 |
| 重排（P2） | **不换序，无重排** |
