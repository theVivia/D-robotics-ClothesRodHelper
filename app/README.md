# 衣序 HangFlow · 交互演示页

> 这是给评委扫码看的"门面页"：**单文件、无外部依赖、无联网、双击即开**。
> 用前端把 **800–2400 mm 可调杆长 + 2–8 个套挂单元**的间距规划、空间告警、急停都演出来；
> 两端有墙、端部余量 50 mm，**杆离墙 50–300 mm 可调（默认 150 mm）**，两者是不同方向的距离；
> 默认行为与真机 P0/P1 一致（不换序）；"抬升越障换序"做成明确的 P2 概念开关，默认关闭。
> 真实硬件接入点见文末「接真设备」。

## 怎么打开

- **最简单**：双击 `app/index.html`，用 Chrome / Edge / Safari 新版打开即可（`file://` 可用）。
- **手机扫码演示**：在项目根目录起一个静态服务，让手机连同一个 Wi-Fi：

  ```bash
  python -m http.server 8000
  ```

  手机访问 `http://<电脑局域网IP>:8000/app/`，用任意二维码工具把地址生成二维码贴在路演屏上。
  页面不需要联网，RDK 现场开热点时也可以直接把 `app/` 丢到中枢上由 FastAPI 托管。

## 屏幕适配

- 手机竖屏 390×844（评委扫码）与桌面宽屏（≥1200）都验证过；960 px 以下单列（杆视图+杆体参数 → 控制台 → 日志）。
- 杆长滑杆和单元数量步进器放在杆视图下方，改参数时不用离开画面；桌面端控制台可独立滚动。
- 480 px 以下再做一轮收紧：顶栏状态换行、风道读数改成 2+1 排列、统计区允许换行，避免窄屏挤压。
- 所有 grid / flex 子项都加了 `min-width: 0`，长文本或日志不会把布局顶宽。

## 演示剧本（约 60 秒）

1. **初始状态**：1200 mm 杆、4 个单元；01–02 净风道只有 4.3 cm，两件高湿衣物（01 / 04）被低湿的 02 / 03 隔开，`风道达标 0/3`。
2. **改杆长**：拖「杆长」到 2000 mm——标尺、墙体、端部余量和风道重算，标题变成 `2.00 m 晾衣杆`（控制面板里同步显示 2000 mm）。
3. **加单元**：点两次「+」，变成 6 个单元；05、06 自动编号并从右墙边滑入，所有单元按目标风道重排。已有单元的编号、衣物名、湿度和电量都保留。
4. **衣摆蹭墙提醒**：把「杆离墙」拖到 60 mm（2000 mm 杆 / 6 单元）——只出现黄色
   「离墙太近，衣摆可能蹭墙（当前 60 mm，建议 ≥120mm）」；这个距离跟端部余量无关。
5. **压到太挤**：杆长 800 mm、单元加到 8 个——只出现红色「太挤了：建议减少单元或加大杆长」，不会静默重叠（杆离墙保持 150 mm）。
6. **点「智能分配」**：保持当前顺序，只按湿度权重拉开间隙（默认 1200/4 单元时是 17.1 / 13.0 / 17.6 cm），
   干-干相邻的那段最窄；日志提示"顺序冲突"，但明确说明 P0/P1 真机不能换序。
7. **（可选）P2 概念演示**：打开控制台里的「P2 概念 · 抬升越障」开关（默认关闭），再点智能分配——
   挡路的低湿单元被"抬起越过"移到最远端，杆视图右上角常驻 `P2 概念 · 硬件需抬升机构` 角标。
8. **拖「目标净风道」/「环境湿度」**：智能基准间隙和分隙实时重算（运行中 0.5 s 防抖）。
9. **一键等距 / 收衣归拢**：等距把各段拉到目标值；收衣时所有单元贴到右端收纳位，保持安全间隙。
10. **拖任意单元**：自动切到手动模式，单元被相邻单元的 3 cm 安全间隙和两侧挡块限制，**不会互相穿过、不会出墙**。
11. **急停**：红色锁定遮罩，拖动 / 模式按钮 / P2 开关 / 杆长 / 杆离墙 / 数量控件全部失效；点「复位并启动」恢复。
12. 逐条拖「衣物湿度」滑杆，再点智能分配，可以演示不同湿度组合下的分隙差异。

## 页面里的数据口径

| 项 | 口径 |
|---|---|
| 杆长 | 800–2400 mm 可调（默认 1200 mm）；两端各有 50 mm 端部余量 |
| 单元数量 | 2–8 个；编号 01–08 是**物理模块编号**，不是衣服编号 |
| 衣物占位 | 每件在杆上的厚度 4.5–8.5 cm，仅用于算净风道 |
| 净风道 | 相邻挂点中心距 − 两件衣物厚度的一半（衣物边缘到边缘） |
| 安全下限 | `g_min = 3 cm`（与 `docs/03-系统总体方案.md` 一致） |
| 目标净风道 | 3–25 cm 可调；"风道达标"按**目标值**判定（容差 0.5 cm） |
| 杆离墙 | 50–300 mm 可调（默认 150 mm）；`d_wall` = 杆中心到墙面的垂直距离，<120 mm 显示黄色衣摆蹭墙提醒，**与端部余量无关** |
| 端部余量 | 50 mm（沿杆方向、挡块/墙内不可用区），拖动和自动排布都不会越过 |
| 湿度状态 | 干 < 35%，潮 35–64%，湿 ≥ 65% |
| 环境湿度 | 40–95% RH，只进入智能分配的基准间隙系数（×0.80–1.70） |
| P2 概念 | 「抬升越障」开关默认关闭；开启只影响动画，不代表真机能力 |
| 电量 / MQTT 时延 | 前端模拟缓慢掉电与抖动，仅用于展示 |

> 注意：初始布局是刻意排成"挤"的状态（01–02 只有 4.3 cm），不是 bug；
> 点一次智能分配就能看到它被打开。

## 智能分配算法（与 planner 同口径）

1. 每件衣物权重 `w = 1 + 2h`（h 为湿度 0–1，越湿权重越大）。
2. 每段间隙的权重 = 相邻两件权重的平均。
3. 基准间隙 = `clamp(目标 × (0.8 + (环境湿度 − 40) / 55 × 0.9), 3, 25)`。
4. 总预算 = 基准 ×（单元数 − 1）段；按权重分配，用 water-filling 把每段夹在 `[3, 25] cm`；
   超出可用长度时压缩间隙并给出空间告警。
5. **默认不换序**（与 P0/P1 真机一致）：两件最湿的衣物被别的衣物隔开时，日志会提示"顺序冲突"，
   但仍然只在当前顺序上分配——干-干相邻的那段最窄，湿区两侧更宽。
6. **P2 概念开关**（默认关闭，控制台里手动打开）：开启后才把挡路的低湿单元整体移到最远端，
   让两件高湿衣物相邻，最大风道给到它们；被移动的单元带"抬起—越过—落下"的弧线，
   杆视图右上角显示"P2 概念 · 硬件需抬升机构"角标。
7. 动画：位置按 `easeInOutCubic` 插值；P2 重排的单元额外做弧线并高亮 `.reorder` 状态，日志同步说明。

## 接真设备（现场替换点）

页面内所有状态都在一个 IIFE 里模拟，按下面几处替换即可接 RDK 中枢：

| 位置 | 现在 | 接真机时 |
|---|---|---|
| `items` 数组 | 初始模拟数据（4 个默认单元） | 用 `/api/state` 或 MQTT `flow/unit-0i/state` 回填 `pos/humidity/battery`；单元表由硬件枚举生成 |
| 杆长 / 单元数量 | 顶部滑杆与步进器（演示配置） | 真机初始化时读配置或现场标定；`state.rodCm`、`items.length` 换成实际值 |
| `runEqual()` / `runSmart()` / `runCollect()` | 本地算目标位置并调 `startMotion()` | 改成 `POST /api/mode {mode, gap}`，由 RDK planner 算目标；或复用同一份几何代码 |
| 目标位置下发 | 无 | MQTT `flow/unit-0i/cmd {"seq":12,"target_mm":420,"speed":45}`（docs/03 §8） |
| 位置更新 | 前端动画 | 订阅 state，收到实测位置再 `render()`；动画只做过渡，不当作真值 |
| 急停 | 本地 `state.estop` | 先发 stop 指令并等硬件回执，再锁定 UI；本地模块按键急停也要同步过来 |
| 湿度 / 电量 | 面板滑杆 / 随机掉电 | 来自传感器或 MQTT state；滑杆只保留为演示开关 |
| P2 概念开关 | 本地 `state.p2Lift` | **不要**接真机；默认关闭，仅用于向评委说明"换序需要抬升机构"的 P2 设想 |
| 标定 | `state.rodCm`、`bulk`、`EDGE_CM=5` | 换成现场实测杆长、衣物厚度与安装余量；墙体位置需按实物确认 |

> 传输层建议以 `docs/03` 和 `docs/07`（软件架构与通信协议）为准；本页只是交互原型，
> 不定义新的协议。

## 已知不足（诚实版）

- 俯视示意图不是 CAD；衣物用色块表达"厚度占位"，不是真实轮廓。
- **默认智能分配不换序**，与 P0/P1 真机一致（单杆连续运动不能交换顺序，只能按 docs/03 §8 串行让位）。
  "抬升越障换序"是默认关闭的 P2 概念开关：开启后才有越过动画，且杆视图会显示"硬件需抬升机构"角标。
  现场演示建议保持关闭，只在被问到 P2 时打开解释。
- 未接 MQTT / WebSocket，刷新页面即回到初始模拟状态；日志只保留最近 8 条，不落盘。
- 只做了单杆 2–8 单元；多杆、升降晾衣架、语音、真实视觉定位都不在原型范围。
- 墙体、端部余量是**俯视示意图**；真实挡块尺寸、墙距、衣摆形状需现场实测后调整 `EDGE_CM`。
- 「杆离墙」`d_wall` 是演示页里手动输入的参数，不来自传感器；真机上应由安装位置确定或由测距得到。
  它只决定衣摆蹭墙提醒，跟沿杆方向的 50 mm 端部余量是两回事。
- 增删单元只演示"换装/拆装"后的排布结果，不模拟真实的机械拆装过程；删除只移除最后一个单元，
  保证编号连续、已有单元数据不丢。
- 单元数量上限 8 是演示页限制，不是产品上限；真实 planner 的规模另按性能评估。
- 触摸拖动依赖 Pointer Events（Chrome / Edge / Safari 新版可用，IE 不支持）；
  局部用了 `backdrop-filter`、`mask-image`，老浏览器降级后视觉略有差异。
- 页面配色和动效是按"现场投屏 + 手机竖屏"调的；未做超宽屏（>1600）和横屏手机的专项优化。
- 所有数字都是演示口径，不是实测结论；产品量化目标以 `docs/_shared-context.md` 为准。

## 自测记录

- 桌面 1400×1050、手机 390×844 渲染检查：无横向滚动（`scrollWidth = clientWidth = 390`，无越界元素）；
  桌面控制台在 1080 高度内可独立滚动，开始/急停按钮常驻在上半屏。
- 浏览器 console 无报错；内联脚本通过 Node `new Function()` 语法检查。
- 无头浏览器自动跑通：初始（1200 mm / 4 单元）→ 杆长 2000 mm + 6 单元 → 杆离墙 60 mm（只出现衣摆蹭墙告警）
  → 一键等距 → 杆长 800 mm + 8 单元（只出现「太挤了」）→ 智能分配 → 打开 P2 概念再分配（多单元换序）→ 急停
  （杆长 / 杆离墙 / 数量 / P2 控件全部锁定）→ 复位 → 减到 2 单元 → 杆长 2400 mm；每一步检查了单元顺序、
  净风道读数、达标数、告警、标尺、墙体宽度、编号连续性和横竖屏溢出。
- 390 竖屏截图（真实 390 CSS 视口）放在 `app/.verify/`：
  `390x844-default.png`、`390x844-rod2000-6units.png`、
  `390x844-wall-warning.png`（2000 mm / 6 单元 / 杆离墙 60 mm）、
  `390x844-overcrowded.png`（800 mm / 8 单元，只有「太挤了」）。
- **验证小提示**：Edge/Chrome `--headless --window-size=390,844` 受最小窗宽限制（实测 `outerWidth=500`、
  `innerWidth=474`），截出来的 390 图其实是 474 宽布局被裁切，看起来"右侧到处溢出"。
  看真实 390 竖屏请用 DevTools 设备模拟（Ctrl+Shift+M → iPhone 14），或把页面放进 390 px 宽的 iframe。
  本页真实 390 视口下 `scrollWidth = clientWidth = 390`，无横向溢出。
